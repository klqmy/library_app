# Контракт учебного API «Библиотека»

Документ описывает интерфейс, с которым работают практические работы ПР4–ПР6. Он же является образцом того описания API, которое студент должен привести в отчёте по индивидуальному проекту.

Базовый адрес по умолчанию: `http://localhost:8080/api`

---

## 1. Общие соглашения

- Формат обмена — JSON, кодировка UTF-8.
- Заголовок `Content-Type: application/json` обязателен для запросов с телом.
- Идентификаторы целочисленные, начинаются с 1.
- Даты передаются строкой в формате ISO 8601: `2026-08-18T10:30:00Z`.
- Все ответы со списками возвращают одинаковую оболочку с постраничной разбивкой.

### 1.1. Оболочка списка

```json
{
  "items": [ /* массив объектов */ ],
  "page": 1,
  "size": 10,
  "total": 137,
  "totalPages": 14
}
```

### 1.2. Формат ошибки

| Код | Смысл | Тело |
|---|---|---|
| 400 | Некорректный запрос | `{ "message": "..." }` |
| 401 | Не аутентифицирован либо токен истёк | `{ "message": "..." }` |
| 403 | Роль не имеет права на операцию | `{ "message": "..." }` |
| 404 | Объект не найден | `{ "message": "..." }` |
| 409 | Конфликт: нарушено ограничение целостности | `{ "message": "..." }` |
| 422 | Ошибка валидации полей | см. ниже |
| 500 | Внутренняя ошибка сервера | `{ "message": "..." }` |

Тело ответа 422:

```json
{
  "message": "Ошибка валидации",
  "errors": {
    "isbn": "Книга с таким ISBN уже существует",
    "year": "Год не может быть больше текущего"
  }
}
```

Ключи объекта `errors` совпадают с именами полей модели — это позволяет показать ошибку прямо в соответствующем поле формы.

## 2. Аутентификация

### `POST /api/auth/register`

Запрос:

```json
{ "username": "ivanov", "password": "Passw0rd!", "email": "ivanov@example.com", "fullName": "Иванов И. И." }
```

Ответ `201`: объект пользователя без пароля. Новый пользователь всегда получает роль `reader`.

### `POST /api/auth/login`

Запрос:

```json
{ "username": "librarian", "password": "librarian123" }
```

Ответ `200`:

```json
{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "eyJhbGciOi...",
  "expiresIn": 900,
  "user": { "id": 2, "username": "librarian", "fullName": "Петрова А. С.", "role": "librarian" }
}
```

`expiresIn` — срок жизни токена доступа в секундах.

### `POST /api/auth/refresh`

Запрос: `{ "refreshToken": "..." }`. Ответ — новая пара токенов в том же формате.

### `GET /api/auth/me`

Требует заголовок `Authorization: Bearer <accessToken>`. Возвращает объект текущего пользователя.

### `POST /api/auth/logout`

Аннулирует токен обновления.

### 2.1. Учётные записи для проверки

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | `admin` |
| `librarian` | `librarian123` | `librarian` |
| `reader` | `reader123` | `reader` |

### 2.2. Права ролей

| Операция | reader | librarian | admin |
|---|---|---|---|
| Просмотр каталога, авторов, жанров, издательств | да | да | да |
| Создание, изменение, удаление книг и справочников | нет | да | да |
| Просмотр читателей и выдач | только свои | все | все |
| Оформление и закрытие выдач | нет | да | да |
| Физическое удаление, восстановление | нет | нет | да |
| Управление пользователями и ролями | нет | нет | да |

## 3. Ресурсы

Единообразный набор операций доступен для `books`, `authors`, `genres`, `publishers`, `readers`, `loans`. Ниже показан на примере книг.

### `GET /api/books`

Параметры строки запроса:

| Параметр | Тип | Назначение |
|---|---|---|
| `search` | строка | поиск по названию и ISBN, регистр не учитывается |
| `genreId` | число | фильтр по жанру |
| `publisherId` | число | фильтр по издательству |
| `authorId` | число | фильтр по автору |
| `yearFrom`, `yearTo` | число | диапазон года издания |
| `available` | `true`/`false` | только доступные к выдаче |
| `sort` | строка | поле и направление, например `title,asc` или `year,desc` |
| `page` | число | номер страницы, с 1 |
| `size` | число | размер страницы, по умолчанию 10, максимум 100 |
| `includeDeleted` | `true`/`false` | включать логически удалённые, по умолчанию `false` |

Пример: `GET /api/books?search=война&genreId=3&sort=year,desc&page=2&size=10`

### `GET /api/books/{id}`

Ответ `200` — объект книги, `404` — если не найдена или удалена логически.

### `POST /api/books`

Роль не ниже `librarian`. Тело:

```json
{
  "title": "Война и мир",
  "isbn": "978-5-17-118366-4",
  "year": 1869,
  "pages": 1300,
  "publisherId": 1,
  "authorIds": [1],
  "genreIds": [2, 5],
  "copiesTotal": 4
}
```

Ответ `201` — созданный объект с присвоенным `id`.

### `PUT /api/books/{id}`

Роль не ниже `librarian`. Тело такое же, как у `POST`. Ответ `200`.

### `DELETE /api/books/{id}`

Логическое удаление: объект получает `deletedAt` и перестаёт попадать в выборки. Роль не ниже `librarian`. Ответ `204`.

### `DELETE /api/books/{id}?hard=true`

Физическое удаление, запись стирается безвозвратно. Только `admin`. Ответ `204`. Если на книгу ссылаются незакрытые выдачи — `409`.

### `POST /api/books/bulk-delete`

Множественное удаление. Тело: `{ "ids": [3, 7, 11] }`. Ответ `200`: `{ "deleted": 3 }`.

### `POST /api/books/{id}/restore`

Восстановление логически удалённой записи. Только `admin`. Ответ `200`.

## 4. Модели

### `Book`

```json
{
  "id": 1,
  "title": "Война и мир",
  "isbn": "978-5-17-118366-4",
  "year": 1869,
  "pages": 1300,
  "publisher": { "id": 1, "name": "АСТ" },
  "authors": [ { "id": 1, "fullName": "Толстой Л. Н." } ],
  "genres": [ { "id": 2, "name": "Роман" } ],
  "copiesTotal": 4,
  "copiesAvailable": 2,
  "createdAt": "2026-08-01T09:00:00Z",
  "deletedAt": null
}
```

При создании и изменении передаются `publisherId`, `authorIds`, `genreIds`; в ответе приходят развёрнутые объекты. Это стандартное для REST различие между представлением на запись и на чтение, и его стоит отразить в отчёте.

### `Author`

```json
{ "id": 1, "fullName": "Толстой Л. Н.", "birthYear": 1828, "country": "Россия", "deletedAt": null }
```

### `Genre`

```json
{ "id": 2, "name": "Роман", "description": "Крупная форма повествования", "deletedAt": null }
```

### `Publisher`

```json
{ "id": 1, "name": "АСТ", "city": "Москва", "foundedYear": 1990, "deletedAt": null }
```

### `Reader`

```json
{
  "id": 1,
  "fullName": "Смирнов П. А.",
  "email": "smirnov@example.com",
  "phone": "+7 900 000-00-00",
  "card": { "id": 1, "number": "RC-000001", "issuedAt": "2026-01-15T00:00:00Z", "expiresAt": "2027-01-15T00:00:00Z" },
  "deletedAt": null
}
```

Связь читателя и билета — один к одному.

### `Loan`

```json
{
  "id": 1,
  "reader": { "id": 1, "fullName": "Смирнов П. А." },
  "book": { "id": 1, "title": "Война и мир" },
  "issuedAt": "2026-08-01T10:00:00Z",
  "dueAt": "2026-08-15T10:00:00Z",
  "returnedAt": null,
  "status": "active"
}
```

Значения `status`: `active`, `returned`, `overdue`.

Дополнительные операции:

- `POST /api/loans` — оформить выдачу, тело `{ "readerId": 1, "bookId": 1, "days": 14 }`. Если `copiesAvailable` равно нулю, возвращается `409`.
- `POST /api/loans/{id}/return` — закрыть выдачу.

## 5. Схема данных

```
Publisher 1 ──< M Book M >──< M Author
                   M
                   │
                   ∨
                   M Genre

Reader 1 ── 1 LibraryCard
Reader 1 ──< M Loan M >── 1 Book

AppUser (username, passwordHash, role, readerId?)
```

Связи:

- `Publisher` → `Book`: один ко многим;
- `Book` ↔ `Author`: многие ко многим;
- `Book` ↔ `Genre`: многие ко многим;
- `Reader` ↔ `LibraryCard`: один к одному;
- `Reader` → `Loan`, `Book` → `Loan`: один ко многим.

Набор покрывает все три типа связей, требуемые в задании на индивидуальный проект.

## 6. Требования к серверу для работы с Flutter Web

Раздел адресован тому, кто разворачивает API.

### 6.1. CORS

Сервер обязан отдавать на каждый ответ:

```
Access-Control-Allow-Origin: <адрес клиента>
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 86400
```

Отдельно обязателен обработчик метода `OPTIONS` на всех адресах: браузер отправляет предварительный запрос перед любым обращением с заголовком `Authorization` или методом, отличным от `GET` и `POST`. Ответ — `204` с теми же заголовками.

Если планируется передавать cookie, значение `Access-Control-Allow-Origin` не может быть `*` — требуется точный адрес и заголовок `Access-Control-Allow-Credentials: true`.

### 6.2. Фиксированный порт клиента

Студенты запускают клиент командой `flutter run -d chrome --web-port=5555`, поэтому в списке разрешённых источников достаточно указать `http://localhost:5555`.

### 6.3. Изоляция данных

При работе на общем сервере записи, созданные одним студентом, видны остальным. Варианты решения: привязка создаваемых записей к учётной записи, ежедневный сброс исходных данных либо запуск мок-сервера каждым студентом локально.
